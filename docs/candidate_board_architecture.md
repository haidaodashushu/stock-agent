# 候选池与观察池

系统只保留两个业务概念：

- **候选池**：最多15只，全部具备买入资格，是模拟盘和实盘操盘实际读取的新开仓范围。
- **观察池**：正式候选加固定100只战略科技股的监测范围；Web 对候选去重，只展示尚未晋升部分。

买入资格不等于实际买入。正常操盘仍结合当时市场、账户、持仓和最新个股证据决定买入或继续观察。

## 候选来源

候选池只接受两个入口：

1. `screen_records`：Hermes 读取完整全市场量化发现证据后给出的每日最终选股。最终入选即直接获得候选资格；
   原始量化TOP池和生命周期状态不能直接进入候选池。
2. `intraday_candidate_promotions`：固定战略观察股出现竞价或盘中雷达信号后，使用
   `config/hermes_stock_entry_policy.md` 独立判断；只有 `promote` 才获得当日候选资格。

`candidate_discovery_history` 和 `candidate_lifecycle` 继续保存全市场跨日发现、改善与失效证据，供下一轮每日
最终选股比较，但它们不是第三套候选池。`opening_auction_watch_candidates` 与 `intraday_radar_candidates`
只是观察证据，也不能直接进入操盘范围。

## 容量和替换

`data/candidate_board.py` 将正式来源物化为不可变、带 `as_of` 的候选版本：

- 上限15只；
- 每日最终选股通常最多10只，为盘中观察股晋升保留空间；
- 候选未满时，晋升股票直接补入；
- 候选已满时，新晋升股票替换每日最终选股中排名最弱的一只；
- 同一股票多来源时只占一个名额并合并证据；
- 原始竞价、雷达和生命周期观察不占名额，也不能触发替换；
- 来源事实没有变化时不重复生成版本。

历史表仍保留旧版本中的 `active/reserve` 字段以便审计，但新版本只写 `active` 正式候选，不再生成备用候选。

## 观察与晋升

固定战略池默认来自 `config/strategic_theme_pool.local.json`（可由
`STOCK_STRATEGIC_THEME_POOL_CONFIG` 覆盖）。集合竞价和盘中雷达持续更新其中股票的行情、量价、资金、
板块与启动迹象。出现动态信号后，`scripts/hermes_candidate_promotion.sh` 独立执行资格判断：

- 不读取模拟盘或实盘账户；
- 不产生交易、仓位或实盘建议；
- 与正常操盘共用唯一的个股买入资格标准；
- 通过后立即刷新正式候选池，有效至当日15:05；
- 未通过的股票继续留在观察池，等待新的事实版本，不会进入操盘范围。

## 操盘消费

模拟盘和实盘只读取最新 `ready` 候选版本，再与各自全部持仓组成决策范围。操盘不能自行从观察池增加股票，
也不能在决策中修改候选成员。候选池为空时，操盘仍正常管理持仓，只是不允许新开仓。

## 调度

- 每日盘前/夜间选股完成最终选择后立即生成目标交易日候选版本；
- 集合竞价最终结果落库后立即触发独立晋升，再刷新候选；
- 盘中雷达在09:50、10:20、10:50、11:20、13:20、13:50、14:20运行，每个新事实版本立即触发独立晋升；
- 晋升与正常半小时操盘完全解耦。
