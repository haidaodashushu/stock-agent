# 财务与板块数据迁移至扶摇

2026-09-22：操盘研究、候选信息补充与默认财务服务统一采用共享财务缓存；板块轮动和成分使用扶摇公开接口。问财资金流、新闻和自然语言查询保持各自来源，不用行情代替资金数据。

## 财务

- 每只股票的成功结果复用24小时，模拟与实盘共享数据库缓存，网络请求前用15分钟租约防止同时刷新同一股票。
- 扶摇利润表识别最新已披露报告期，指标接口取得ROE、ROA、毛利率、净利率、同比增长及负债率；利润表补每股收益、现金流量表补经营现金流。
- 仅缺少必需字段时查询一次问财。相同报告期才补字段；问财报告更新时整份切换，不把旧报告的字段混入新报告。保留真实0和缺失null，逐字段记录来源。
- 财务同步写入既有financial_factors，供选股使用；缺失字段不补0。成功但不完整的数据仍复用一天，避免每小时重复消耗两边接口。完全失败时保留旧事实及原始采集时间，1小时后允许刷新。
- 旧的有效缓存自然到期后转入新优先级，不强制刷新所有股票。

## 板块

- 使用同花顺概念/行业目录、批量指数行情、指数日线及成分接口，不调用问财的轮动排名/所属概念查询。主动注入旧provider的调用者仍可以使用旧适配器契约。
- 目录和成分共享缓存7天；批量行情缓存15分钟；日线缓存18小时。轮动快照沿用调用方的缓存周期。
- 每次轮动刷新最多新增6份历史、6份成分；持仓/候选成分补充最多新增3份。HTTP 429和业务码4001都会进入共享Key冷却；单项刷新失败退避15分钟。
- 成分按板块原子替换，移除真实退出的股票，同时保留其其他板块。已获得完整扶摇成分的板块，以该来源为准，不让旧问财或静态名单恢复已退出关系。空响应不清空原名单。
- 轮动收益按5/21/63/126个交易日计算；不再猜测问财动态列对应哪一段期限。与原来日历月查询不是完全相同的时间窗，输出明确标注该口径。
- 冷缓存按当日涨幅优先补历史，随后对全部已有有效历史的板块使用原量价评分公式；覆盖不足标partial并给出catalog_count、quote_count、history_ready_count。缺历史的板块保留行情、不给轮动加分。排名仅代表当前已覆盖范围。
- 主力资金值为null、fund_flow_status=unavailable，不授予资金潜伏/吸筹标签。当日涨幅、成交额、数据时间、历史完整性随板块证据传给LLM。
- 扶摇的资金流、新闻事件和高频动向公开文档标注不开放外部接入，本次没有尝试接入这些受限接口。

## 验证与预热

相关测试覆盖优先级、无问财调用的缓存命中、缺失补充、报告期隔离、未来公告过滤、4001冷却、成分删除与旧来源遮蔽、历史窗口、时间戳/标的校验、缺失历史不加分。

真实接口在独立数据库验证：科瑞技术中报全部核心财务字段取得成功、问财调用0次，二次刷新请求0；取得710个行业/概念目录及710份行情，取得历史日线及成分。该单次验证证明接口与字段可用，不代表未来持续可用。

首次启用可用下面的脚本预热重点板块，不产生交易或消息：

```bash
python scripts/warm_fuyao_sectors.py --codes 002957,600356 --limit 30
```

`--limit`控制板块数，优先现有股票归属，其次按当日涨幅；其余缺失项在正常刷新中按预算逐步补齐。缓存存放在实际数据库路径旁的`.fuyao-cache`目录，两账户共享。运行命令必须加载生产既有环境文件，不能把临时测试数据库当成账户库。
