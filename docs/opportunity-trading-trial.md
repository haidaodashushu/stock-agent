# 持续机会操盘试运行

基于main `5c8dbc4`，2026-09-20开始准备。此版本不修改成交价格偏离校验，不加入完整牛熊分类器。

## 运行方式

- 日常选股、竞价、雷达和晋升保留。正式选股机会形成独立档案，默认再观察5个交易日；退出今日榜单不删除。
- 半小时操盘每轮最多8只候选，其中需要新建或更新研究的候选最多3只；其余使用已有有效研究做增量判断。未入当轮的机会仍保留并监测，按未研究/最久未研究排序。全部持仓另行保留，数量不计入候选上限。首次补建持仓研究时可能较慢。
- 全部实际持仓仍进入账户决策及风险监控，执行器的现金、手数、T+1、容量与账户隔离继续生效。
- 交易时段每3分钟批量取报价，复用45秒内的有效报价；观测逻辑不调用LLM、不取全量分时、不查询付费资金接口。正式候选池发生变化时额外执行一次监测，再启动受账户锁保护的事件处理进程；这部分增加的报价请求会记入监测统计。
- 价格触及模型明确记录的重评/失效线、持仓数量变化、已入库的重要新增消息产生事件。初次未建档机会也排队研究。
- 每分钟检查事件队列，单账户串行，无每日批次上限或额外账户冷却，每批最多30只事件候选，其中需要新建或更新研究的候选最多3只；有效研究可直接复用。结构/快速下跌/重要负面风险优先，全部实际持仓的事件合并入同轮复核，不占候选名额。
- 保留原半小时账户复核，每只股票的计划复核间隔默认30个交易分钟（可设15—240分钟）。新有效事件不必等待该股票定时到期；计划到期也不因别的股票刚做过复核而额外等待，但仍受账户互斥、去重和分批约束。程序不保证零延迟。
- 同一股票、同一计划条件、同一天的事件去重。无法确认执行结果的批次进入needs_review，不自动重放。
- 普通旧候选的缺失研究（research_due）保留待办，由常规定时任务的研究名额处理，不单独启动账户操盘；新机会、计划到期、行情和风险事件仍可及时触发。过期研究不会冒充有效研究。
- 模型已看到的价格条件，不因计划价格/状态更新而重复唤醒；新观察到的穿越、到期、新消息和快速下跌仍可触发。旧计划遗留的未处理价格事件会失效，避免按旧阈值重跑。
- 消息区分“定时操盘”和“事件复核”，后者列明触发原因及股票数量。事件复核仅在执行回执包含模拟成交、新实盘买卖建议或逐项执行异常时推送；纯持有/观察不推送。定时报告和任务失败告警保留。所有完成的决策、研究更新、复核计划、完整报告及通知策略原因仍存档，静默不影响后续监测。
- 事件模型开始前刷新股票事实。报价缓存最多45秒；分时最多10分钟，事件相关股票强制补拉；资金缓存最多10分钟并显式标为cached。所有缓存保留源时间。
- 源时间缺失/过期的报价和未经验证的上一交易日前复权日线不得支持新买或加仓；缺其他辅助证据可以继续研究，不冒充0。
- 历史候选只有观察权。新买必须在watch_plan明确requalified及当轮依据，并继续通过账户执行门槛。
- 模拟成交和实盘人工建议维持原语义。watch_plan描述判断，持仓数量来自实际账本；监测器观察成交回填后继续更新事件。

## 数据修复

分时校验源交易日、排序、重复、缺口和累计量额；量与额共同按腾讯累计口径处理，VWAP越界单独降级。第一半小时价格变化与前后两个半小时量额比较分别报告可用性。

日线从fqkline的明确qfqday分支读取，重建目标为320根的完整前复权技术窗口（上市不足时使用源端实际记录），并记录起止日期和来源。腾讯成交量从手转为股，缺失成交额保留null。拒绝把raw day结果标为qfq。旧窗口外历史不删除；操盘技术指标只使用经本次源验证的窗口。首次使用/日线更新后按需补齐，夜间更新也采用此入口。

资金流校验字段后缀日期，主力字段缺失时整条不可用；其他字段缺失保留null。未带日期的返回不能冒充历史查询。主力净占比保留正负方向。

补入数据库已有财务、新闻来源URL、持仓原选股信息、逐股机会档案。快照as_of取采集完成时间，同时保留开始时间和各源时间。920市场映射和北交所禁买规则统一修复。

## 部署和回退

使用独立worktree，不修改main源码。提交配置默认enabled=false；主机安装配置另存ignored文件，启动脚本读取其中路径。

安装：`scripts/configure_opportunity_trial.py --production-root /path/to/production`。

安装器保存原cron，仅替换STOCK_AGENT_RUNTIME块内入口目录并新增三个监测/事件入口，保留原调度时刻、模型环境变量、块外任务和消息路径。私有JSON配置及Python环境链接至原目录；数据库通过STOCK_DB_PATH明确指向生产账本。源数据缓存共享，账户分区仍独立。不得同时手工启动旧、新两套操盘。

回退：同一命令加`--rollback`。如cron被其他任务再次修改，工具拒绝覆盖，需要保留后续改动后单独恢复该块。回退只恢复运行入口，不倒滚真实成交和已产生的账本。

## 研究档案与实时变化分层

股票研究按代码跨账户共享，记录版本、事实指纹、证据时间、有效期、公司判断、历史趋势判断、风险及更新条件。watch_plan和上次完成决策的比较基准按账户隔离。财务原始字段优先从本地日缓存读取；启用financial_enrichment后每轮最多补充3只到期或缺失的资料，现有问财优先、扶摇补缺，监控不查询财报。日线指标按验证窗口版本缓存，窗口变化时重新计算。

研究默认有效5个交易日；财务实质字段、重要入库新闻或机会路线变化，以及研究到期，会标记refresh_required。行情涨跌本身不会机械使整份公司研究失效，但当轮日线、分钟、市场板块和新消息仍送给模型；模型发现结构推翻原研究时也能主动更新。旧研究失效后仍展示其历史结论及日期，明确不能视为当前有效结论。

有效研究配合当前行情进入半小时决策。默认压缩重复的财务原始字段；stock_evidence的include_research_details=true可展开同一快照的原始财务字段，供核验或改写研究使用。changes_since_last_decision显示相对本账户上次完成决策的价格变化、日线更新和研究输入变化；源行情不可靠时价格差为空。

研究更新必须引用当前快照的facts_version，并通过长度、状态校验。数据待补不能支持新买或加仓，但风险降低类退出可先处理。研究在成功执行回执后保存，跨账户同时更新采用版本比较，迟到版本不能覆盖已保存的新版本。研究资料只描述股票，不包含其他账户的仓位、现金或权限。
